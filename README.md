### 7주차

- 이번 주에 한 일: 프로토타입을 실제로 쓸 수 있는 형태로 확정했다. 먼저 로그인 화면을 따로 만들어, 앱을 열면 로그인·회원가입과 "로그인 없이 이 기기에서 쓰기" 중에서 고르게 했다. 시간도 실제 시계로 동작하게 바꿨다. 자정이 되면 날짜가 저절로 넘어가고, 새벽 2시가 지나면 전날이 자동으로 마감되어 기회 사용·먼지·퇴화가 처리된다. 며칠 동안 앱을 열지 않았어도 다시 열면 그동안 빠진 날이 한 번에 처리되게 했다. 시각이나 단계를 바꾸고 하루를 건너뛰는 버튼은 점검할 때만 필요하므로 설정 안의 개발자 도구로 옮겨 평소에는 보이지 않게 했다. 직접 써 보다가 메모가 저장되지 않는 버그를 발견해 고쳤고, 같은 와이파이에 연결된 휴대폰으로도 접속해 로그인한 기록이 그대로 보이는지 확인했다.
- 새롭게 알게 된 것: 시연할 때 편하려고 넣은 기능이 실제 사용에는 방해가 된다는 것을 알게 되었다. 시각을 직접 고르는 기능은 규칙을 확인할 때는 편했지만 실제 사용자에게는 필요 없고 앱이 미완성처럼 보이게 만들었다. 그래서 지우는 대신 숨겨 두고 점검할 때만 꺼내 쓰기로 했다. 또 화면에 글자가 남아 있다고 저장된 것은 아니라는 것도 알게 되었다. 메모 버그가 그랬는데, 저장 버튼을 누르는 순간에만 메모를 읽고 있어서 그 뒤에 쓴 글은 화면에만 남아 있다가 화면을 다시 그릴 때 사라졌다. 이를 통해 눈에 보이는 것과 실제로 저장된 값을 따로 확인해야 한다는 것을 배웠다.
- 어려웠던 점: 자동 마감을 만드는 것이 생각보다 까다로웠다. 날짜가 바뀌는 시점(자정)과 기록을 마감하는 시점(새벽 2시)이 달라서 둘을 따로 처리해야 했고, 며칠 만에 앱을 열었을 때 빠진 날을 순서대로 되짚으며 기회와 연속 일수를 계산하는 부분이 헷갈렸다. 날짜를 하루씩 넘겨 기회 2번을 쓰고 5일 연속 빠뜨렸을 때 게이지가 제대로 줄어드는지 직접 확인하면서 맞췄다.
- 다음 주에 할 일: 발표 자료를 마무리할 것이다. 구조도·실행 흐름도, 주요 기능, 프론트엔드·백엔드·DB 구성을 발표용으로 정리하고, 시연 순서(컨디션 입력 → 체크리스트 → 성장 → 빠진 날 → 로그인)를 정해 확인해 볼 것이다. 깃허브 저장소도 정리해 README와 함께 올릴 것이다. 그리고 성장 기준 4개가 적당한지는 아직 며칠 써 보지 못해서, 남은 기간 동안 실제로 사용하며 확인할 것이다.
